## Prerequisites

| Requirement | Version | Notes |
|---|---|---|
| Node.js | 20+ | Developed on 24.19.0. The app itself needs nothing exotic |
| npm | 10+ | Bundled with Node |
| A funded Tempo Moderato address | — | Only needed to actually settle payments |

There is **no** Linux/macOS requirement, no Redis, no database and no Docker dependency. If you only want to read the docs and hit the free routes, no credentials at all.

## Installation

### 1. Clone and install

```bash
git clone https://github.com/your-org/spigot.git
cd spigot/spigot-docs
npm install
```

The app lives in `spigot-docs/`, not at the repo root.

### 2. Environment file

```bash
cp .env.example .env.local
```

`.env.local` wins over `.env`, and keys already present in the process environment are never overridden by either.

### 3. Minimum to boot

```bash
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=pk_...
CLERK_SECRET_KEY=sk_...
```

`app/layout.tsx` mounts `ClerkProvider`, `components/nav.tsx` renders the sign-in buttons, and `proxy.ts` runs `clerkMiddleware`. Without these the app still builds, but every page renders a provider with no publishable key.

### 4. Minimum to settle payments

Pick one signer.

```dotenv
# Option A — local key. Simplest, works everywhere.
TEMPO_SIGNER=privateKey
TEMPO_PRIVATE_KEY=0x...
TEMPO_MERCHANT_ADDRESS=0xYourAddress
```

```dotenv
# Option B — Dynamic MPC. No single party can sign alone.
TEMPO_SIGNER=dynamic
DYNAMIC_ENVIRONMENT_ID=...
DYNAMIC_API_TOKEN=...
DYNAMIC_WALLET_PASSWORD=...
DYNAMIC_THRESHOLD_SIGNATURE_SCHEME=TWO_OF_TWO
DYNAMIC_BACKUP_TO_CLIENT_SHARE_SERVICE=true
DYNAMIC_WALLET_STORE=.dynamic-wallet.json
```

The app payment broadcaster currently supports `TEMPO_SIGNER=privateKey` only. Dynamic wallet setup is available for other signing flows, but app settlements remain disabled until Dynamic broadcast support is implemented.

`DYNAMIC_WALLET_PASSWORD` is required whenever `DYNAMIC_BACKUP_TO_CLIENT_SHARE_SERVICE` is on, which is the default. `isTempoSignerConfigured()` reports `false` unless every variable in `DYNAMIC_REQUIRED_ENV` is present, so a partial Dynamic config is reported as unconfigured rather than failing mid-payment.

> `TEMPO_MERCHANT_ADDRESS` has no fallback. `/api/pay` returns `503` until it is set to a valid wallet you control. The zero address and the known `0x…dEaD` address are rejected before any transfer is sent.

### 5. Fund the wallet

```bash
curl -X POST https://rpc.moderato.tempo.xyz \
  -H "content-type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tempo_fundAddress","params":["0xYourAddress"]}'
```

### 6. Minimum to run the agent

```dotenv
LLM_PROVIDER=gateway
LLM_GATEWAY_API_KEY=...
```

Or `LLM_PROVIDER=openai` with `OPENAI_API_KEY`, or `LLM_PROVIDER=gemini` with `GEMINI_API_KEY`. `getChatModel()` throws a message naming the missing variable rather than letting it surface as a 500 mid-call. Without a key the agent routes do not work; everything else does.

All three providers are reached through the same OpenAI-compatible client, so each is only a base URL and a key. A Google AI Studio key works as-is:

```dotenv
LLM_PROVIDER=gemini
GEMINI_API_KEY=...
```

That resolves to `https://generativelanguage.googleapis.com/v1beta/openai` with model `gemini-3.8-flash`, Google's OpenAI-compatibility layer. For any other OpenAI-compatible host set `LLM_BASE_URL` instead — it overrides the base URL for whichever provider is selected, so OpenRouter or a local vLLM needs no code change.

### Tempo signer and settlement

| Variable | Required | Default | Used by |
|---|---|---|---|
| `TEMPO_SIGNER` | no | `privateKey` | App settlement currently broadcasts with `privateKey`; Dynamic broadcast is not implemented |
| `TEMPO_PRIVATE_KEY` | for `privateKey` | — | `lib/tempo/signer.ts` |
| `TEMPO_MERCHANT_ADDRESS` | required for settlements | — | `lib/tempo/payment.ts` |

Set `SPIGOT_SELF_URL` when the agent runs in a process that cannot reach itself at `localhost` — for example a container that forwards to the host. Leaving it at the default in a container makes the agent call itself and never connect.

### Paid endpoint upstreams

Neither provider needs a key at the volumes this app sees, so these are optional.

| Variable | Required | Default | Used by |
|---|---|---|---|
| `COINGECKO_API_KEY` | no | free tier | `lib/data/market.ts` — sent as a bearer token when set, for a higher rate limit |

Open-Meteo has no key option. Responses are cached in-process: 60s for the market snapshot, 15 minutes for weather, 24 hours for city geocoding.

## Running

```bash
npm run dev            # http://localhost:3000, Turbopack
npm run build          # production build
npm run start          # serve the build
npm run types:check    # tsc --noEmit
npm run lint           # see Known Issues
```

### Verify

```bash
curl -s localhost:3000/api/health
# {"status":"ok","timestamp":"..."}

curl -s localhost:3000/api/pay
# reports signer, merchant-address, and payment readiness without sending a transfer
```

`configured: false` means no usable signer — see step 4.

### CLI walkthrough

A separate ESM script under `cli/tempo/` that exercises Dynamic wallet creation, faucet funding and `mppx.fetch` against an external 402 endpoint.

```bash
npm run self-test      # offline, no credentials, no network
npm run cli:dry        # local private key, full sequence
npm run cli            # Dynamic MPC against Moderato
```

`self-test` asserts the things that are easy to break silently: the signed bytes start with `0x76`, the sign payload equals `Transaction.z_TxEnvelopeTempo.getSignPayload`, the bytes handed to Dynamic hash to that same payload, a stale signature is never signed over, sponsored envelopes come out as `0x78`, EIP-1559 falls back to `0x02`, and `signMessage`/`signTypedData` recover to the account address.

## Deployment

Any host that runs Node and keeps one process. `npm run build && npm run start`.

### Things that will bite you

- **One instance only.** The replay `Map`, `lib/store.ts` and the LangGraph `MemorySaver` are all in-process. A load balancer without sticky sessions means two instances can each redeem the same receipt.
- **Keep the process alive.** The server holds the configured signing wallet and signs on demand. Any instance restart drops transactions, revenue history and agent memory.
- **Set `TEMPO_MERCHANT_ADDRESS`.** Without a valid merchant address, settlement is disabled.
- **`TEMPO_PRIVATE_KEY` in a secret manager**, never in the image or the repo.
- **Node 20+.** No native build step is needed, so most PaaS images work as-is.

### Vercel

Workable for the read-only surface — docs, landing page, free routes. The paid flow needs the signing process to persist between requests, which serverless functions do not guarantee, and the in-memory store resets on every cold start.

## Known issues

| Issue | Detail |
|---|---|
| `npm run lint` fails | `Error: typescript-eslint does not support TS 7.0.` The project pins `typescript: ^7.0.2` while `eslint-config-next` 16.3.5 does not support it. Fix by dropping TypeScript to 6.x, or by upgrading the eslint config. Not done here because it is a dependency-policy call |
| `LLM_GATEWAY_API_KEY` ships empty in `.env.example` | `/api/agent/run` and `/api/agent/chat` cannot run until you fill it in. Everything else works without it — the paid endpoints, the demo page and the full three-call handshake |
| Agent conversation memory is not wired | `threadId` is accepted and returned, but checkpoints are never enumerated or reused |
| Paid callers can hit a 502 they already paid for | Upstream (Open-Meteo, CoinGecko) is fetched after the receipt verifies, by design. An outage between the two leaves the caller charged. Responses carry the `payment` block so the charge is traceable |

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `configured: false` on `/api/pay` | No signer | Set `TEMPO_SIGNER=privateKey` + `TEMPO_PRIVATE_KEY`, or `dynamic` + all three Dynamic vars |
| `POST /api/pay` returns `503` | Signer unconfigured | Same as above |
| Clerk provider error on every page | Missing publishable key | Set `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` |
| `LLM_GATEWAY_API_KEY is not set` | Agent model unconfigured | Set the key, or switch `LLM_PROVIDER` to `openai` or `gemini`. Only the agent routes are affected — `/demo` performs a real payment without one |
| Agent run returns `fetch failed` | `SPIGOT_SELF_URL` unreachable from the agent's process | Point it at a reachable base URL |
| `Weather upstream unavailable` / `Unknown city "…"` | 502: paid route, but Open-Meteo could not answer | Check the spelling, or retry. The payment already settled and is in the response's `payment` block |
| `Market data upstream unavailable` | 502: CoinGecko failed or rate-limited | Wait 60s, or set `COINGECKO_API_KEY`. Responses are cached 60s per instance |
| `Could not pay for the tool` in the agent chat | Agent wallet balance below the tool price | Fund it — the balance is on `/api/agent/status`, in `balanceToken` |
| `Paid 0.001, need at least 0.005` | Underpaid | The price is a floor |
| `Payment settled to 0x…, not the merchant address` | Wrong recipient | Omit `to`, or set `TEMPO_MERCHANT_ADDRESS` and retry |
| `Receipt has already been redeemed` | Replay | Pay again for a new receipt |
| `Receipt is for /api/other, not /api/weather` | Receipt bought for another route | `endpoint` is bound into the receipt |
| `Receipt belongs to agent X, not Y` | `X-Agent-Id` mismatch | Match it, or omit the header |
| Faucet call fails | Rate limited | Wait, or send tokens from another account |
| Lint dies on typescript-eslint | TypeScript 7 vs the eslint config | See Known issues |
