> Metered stablecoin tap for AI agents — a 402-paid API gateway backed by the Tempo chain and Dynamic MPC wallets.

## Project Overview

Spigot is a pay-per-call API gateway that lets you charge per request in stablecoins. It is built on:

- **Tempo** — an L2 where a transfer is a TIP-20 `transfer` call; settles in seconds for fractions of a cent
- **A signing strategy** — either a local `TEMPO_PRIVATE_KEY` or a Dynamic MPC wallet via `TEMPO_SIGNER=dynamic`
- **HTTP 402** — the status code for "pay first"; the server holds the wallet and the client never signs anything

Paid endpoints answer `402` until a receipt is attached. Each receipt is re-verified against Tempo before the endpoint serves anything.

### What this is not

Stated plainly, because several of these are easy to assume:

- **The receipt is not a signature.** It is base64url JSON naming a transaction. Everything in it can be forged by whoever presents it, which is why verification re-reads the chain.
- **Replay protection is per-process.** Redeemed hashes live in a `Map` in the server. A second instance would not see them.
- **No rate limiting.** Nothing caps request volume. `/api/pay` is unmetered.
- **No webhooks.** There is no outbound notification code.
- **No database.** Transactions, usage logs and revenue history are in-memory and reset on restart.

## Quick Start

### Prerequisites

- **Node.js** ≥ 20 (Linux or macOS for full MPC support)
- **npm** ≥ 10
- A [Dynamic](https://www.dynamic.xyz/) account with an environment ID and API token

### Installation

```bash
# Clone the repository
git clone https://github.com/your-org/spigot.git
cd spigot

# Install dependencies
npm install

# Configure environment
cp .env.example .env
# Edit .env with your Dynamic credentials
```

### Run the Gateway

```bash
npm run dev            # http://localhost:3000
npm run types:check    # tsc --noEmit
npm run lint           # see Known Issues — currently broken
```

### CLI

```bash
npm run self-test      # offline, no credentials needed
npm run cli:dry        # local private key, full flow
npm run cli            # Dynamic MPC signing against Moderato
```

### Check it works

```bash
$ curl -s localhost:3000/api/health
{"status":"ok","timestamp":"2026-10-02T15:11:59.718Z"}

$ curl -s localhost:3000/api/pay
{"configured":true,"address":"0x19E7E376…","chainId":42431,…}
```

`configured: false` means no signer — see [Setup](/docs/setup).

## Feature List

### Core Features

- **402 Payment Required Flow** — Automatic detection and settlement of payment challenges
- **MPC Wallet Integration** — Threshold ECDSA signatures via Dynamic's 2-of-2 scheme
- **Tempo Chain Support** — Custom transaction serialization (type `0x76`, fee-payer `0x78`)
- **Stablecoin Settlement** — PathUSD, AlphaUSD, BetaUSD, ThetaUSD (TIP-20 tokens)
- **Faucet Integration** — One-command testnet funding via `tempo_fundAddress`
- **Dry-Run Mode** — Full payment flow testing without Dynamic credentials
- **Self-Test Suite** — Offline validation of all signing and serialization logic

### Security Features

- **Key Shares Never Leave Dynamic** — Client share backed up encrypted; server share held by Dynamic
- **Password-Protected Recovery** — Client share recoverable with wallet password
- **Transaction Policy Engine** — Dynamic evaluates every signing request against configurable policies
- **No Private Keys in Memory** — MPC ensures no single party ever holds the full key

### Developer Experience

- **Zero-Config Faucet** — Automatic testnet token minting on first run
- **Wallet Persistence** — Metadata stored locally; key shares recovered on demand
- **CLI Flags** — Override any config value from the command line
- **Comprehensive Logging** — Step-by-step progress with Dynamic SDK integration
