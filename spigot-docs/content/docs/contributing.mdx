## Layout

```
app/            Next.js App Router — pages, API routes, layouts
  api/          Route handlers
components/     React components (hero scene, nav, markdown, search)
lib/            Application logic
  pricing.ts    Canonical endpoint prices
  store.ts      In-memory transactions, usage logs, revenue
  llm.ts        Env-selectable chat model
  agent-graph.ts LangGraph run: decide → pay → call
  tempo/        chain.ts, signer.ts, dynamic-signer.ts, payment.ts
content/docs/   This documentation (MDX)
cli/tempo/      Standalone ESM walkthrough (JS)
proxy.ts        Clerk middleware + docs content negotiation
```

## Code style

### TypeScript

Strict mode, no implicit `any`, no non-null assertions on values you have not just checked. Prefer narrowing over casts:

```ts
// good
if (!token) throw new Error(`Unknown token: ${symbol}`);
return TOKENS[token];

// avoid
return TOKENS[token]!;
```

### Comments explain why, not what

The comment earns its place by recording something the code cannot say — a constraint, a past bug, a non-obvious ordering requirement.

```ts
// good — records the failure this prevents
// `markRedeemed: false` matters: this check and the endpoint's own check run
// on the same receipt, so consuming the guard here would make the endpoint
// reject its own payment as a replay.
await verifyReceipt(txHash, { endpoint, minAmount, markRedeemed: false });

// avoid — restates the line below
// Send the payment
await settlePayment({ amount, endpoint });
```

`lib/pricing.ts` and `lib/llm.ts` both carry a header comment naming the drift they exist to prevent. Keep that habit.

### Naming

| Element | Convention | Example |
|---|---|---|
| Files | `kebab-case.ts` | `agent-graph.ts`, `dynamic-signer.ts` |
| Components | `PascalCase.tsx` | `HeroScene`, `Markdown` |
| Functions, variables | `camelCase` | `verifyReceipt()` |
| Constants | `UPPER_SNAKE_CASE` | `MAX_TRANSACTIONS`, `TEMPO_MODERATO` |
| Types, interfaces | `PascalCase` | `VerificationResult` |
| React refs | `useRef<T>()` named `xRef` | `canvasRef` |

### Imports

Node builtins, then external, then `@/lib` and `@/app`, separated by blank lines. No default exports in `lib/` — named only.

```ts
import { NextResponse } from 'next/server';
import { z } from 'zod';

import { priceOf } from '@/lib/pricing';
import { verifyReceipt } from '@/lib/tempo/payment';
```

### Errors

Throw with a message that names the fix. Never log key material, receipt contents beyond a hash, or env values.

```ts
// good
throw new Error('LLM_GATEWAY_API_KEY is not set. Add a key to .env.local, or set LLM_PROVIDER=openai with OPENAI_API_KEY instead.');

// bad
throw new Error('config error');
```

Route handlers return structured JSON — `{ error, message }` at minimum — rather than throwing, so the client gets something it can branch on.

## Checks

```bash
npm run types:check    # tsc --noEmit — this one must pass
npm run self-test      # offline signing and serialization assertions
npm run lint           # see Known Issues; currently broken on TS 7
```

There is no test framework and no unit test suite. Verification is manual against a running server:

```bash
curl -s localhost:3000/api/health
curl -s localhost:3000/api/weather                       # 402 with the price

RECEIPT=$(curl -s -X POST localhost:3000/api/pay \
  -H 'content-type: application/json' \
  -d '{"amount":0.005,"endpoint":"/api/weather","agentId":"agt-0000"}' | jq -r .receipt)

curl -s localhost:3000/api/weather -H "Payment-Receipt: $RECEIPT"   # 200
curl -s localhost:3000/api/weather -H "Payment-Receipt: $RECEIPT"   # 402, replay
```

A payment change is not done until that sequence passes end to end, including the replay rejection on the last call.

## Pull requests

### Branch names

`feat/`, `fix/`, `docs/`, `refactor/`, `chore/`.

### Commits

[Conventional Commits](https://www.conventionalcommits.org/):

```
fix: decode transfer recipient from calldata instead of trusting receipt
refactor: centralize endpoint prices in lib/pricing.ts
docs: describe the three-call 402 handshake accurately
```

### Checklist

- [ ] `npm run types:check` passes
- [ ] Payment paths verified end to end if `lib/tempo/payment.ts` was touched
- [ ] No new price literal — read `lib/pricing.ts`
- [ ] New env var added to `.env.example` and to `content/docs/setup.mdx`
- [ ] No secrets, keys, or receipt bodies in code or logs
- [ ] Docs updated if behaviour changed — this is the failure mode worth guarding. The docs previously described `Payment-Required` headers the server never emitted, a signed receipt format the code does not produce, `npm run run` instead of `npm run cli`, Redis rate limiting that did not exist, and `src/ui/` paths from before the Next.js migration.

## Where bugs have hidden

Worth knowing before you go looking.

| Area | What went wrong before |
|---|---|
| `lib/pricing.ts` | Prices were written out in four places and drifted — the directory advertised $0.015 while the paywall charged $0.005, so agents overpaid 3x |
| `lib/tempo/payment.ts` | Verification trusted the unsigned receipt's own `to` field. Anyone could mint a receipt naming a transfer to their own wallet and redeem it. Now the recipient is decoded from calldata and compared to `getSettlementAddress()` |
| `lib/agent-graph.ts` | A pre-flight `verifyReceipt` consumed the replay guard, so the endpoint rejected the agent's own fresh payment. Tool args were never forwarded, so the agent paid for `city` and got whichever city it got |
| `app/api/agent/fund/route.ts` | `resolveToken` sat outside the `try`, so an unknown token threw an unhandled rejection |
| `app/api/chat/route.ts` | `req.json()` had no `.catch()`, so an empty body crashed the handler. Fixed — it now answers `400` |
| `lib/store.ts` | Arrays grew without bound; the revenue history was seeded with fake values |
| `components/hero-scene.tsx | Left a `requestAnimationFrame` loop running after unmount and double-initialised the WebGL context under StrictMode |

## Things marked as done that are not

Flagged rather than quietly left in place. Fixing any of these is a welcome PR.

| Location | Problem |
|---|---|
| `lib/agent-graph.ts` | `threadId` is accepted and returned, but `MemorySaver` checkpoints are never enumerated or evicted, so a repeated `threadId` does not actually resume the conversation its name implies |
| `lib/tempo/signer.ts` | `toNumber()` still assumes 18 decimals for the native coin, which is why `getNativeBalance()` returns figures like `4.24e+57`. No route reports it any more — `/api/agent/status` reads the TIP-20 balance instead — but the function itself is still wrong for anyone who calls it |
| `app/api/premium-data`, `app/api/weather` | Both fetch upstream *after* verifying the receipt, so an upstream failure means a caller has paid for a 502. Deliberate: verifying first is what stops unpaid callers costing a third party a request. The alternative — fetch first — turns the endpoints into an open proxy for a free API |
| `package.json` | `typescript: ^7.0.2` breaks `npm run lint` |
